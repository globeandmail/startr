# AGENTS.md

This is a [startr](https://github.com/globeandmail/startr) project — The Globe and
Mail's template for data journalism analysis in R. Read this before editing anything
in `R/`, `config.R`, or `run.R`.

## Conventions (non-negotiable)

These come from the project's own philosophy on data analysis — follow them exactly,
don't "improve" on them:

- **`data/raw/` is read-only.** Never edit, overwrite, or programmatically mutate files
  there. If a raw file needs corrected values, create a *new* file with the corrections
  and join it during the processing step — never touch the original.
- **Everything in `data/processed/`, `data/out/`, `data/cache/`, and `plots/` is
  disposable.** These are regenerated by running the pipeline (see below) and are
  gitignored. Never hand-edit a file in these directories — fix the code that produces
  it instead. Don't add these paths to version control.
- **Never overwrite or reassign a variable**, including via a repeated `mutate()` on
  the same column name. Give the new value a new name.
- **Run code sequentially, top to bottom.** Don't rely on out-of-order execution
  producing the same result — it won't be reproducible for the next person (or agent).
- **Match the tidyverse style guide.** `.lintr` enforces most of this; run `lintr::lint_dir()`
  if unsure.
- **Don't optimize prematurely.** Only address performance if a step is actually slow
  (multiple minutes+). Clear, simple code beats clever code here.

## Pipeline structure

Four files, run in this order by `run.R`, each with a single, narrow job:

1. **`config.R`** — declares packages (via `initialize_startr(packages = c(...))`) and
   raw data file paths. Sourced first by `run_config()`.
2. **`R/process.R`** — reads from `dir_data_raw()` only, cleans/tidies, writes the
   result to `dir_data_processed()` (typically as `.feather`). Never do analysis here.
   Variables created in this file are wiped from the environment after it runs
   (`should_clean_processing_variables`), so nothing here should be depended on by
   later steps except what's written to disk.
3. **`R/analyze.R`** — reads from `dir_data_processed()` only, never from `dir_data_raw()`.
   All grouping/summarizing/filtering happens here.
4. **`R/visualize.R`** — builds plots from objects created in `analyze.R`, writes them
   with `write_plot()`.

`R/functions.R` holds shared helper functions used across the above; it's sourced
automatically by `run_config()`.

Each stage's inputs and outputs are files under `data/`, not shared in-memory state —
if you're trying to figure out what a given stage depends on, check what it reads from
disk, not what an earlier script left in the global environment.

## Running the project

- Full pipeline: source `run.R` (or `Rscript run.R`).
- A single stage, from an R console: `run_config()`, then `run_process()`,
  `run_analyze()`, `run_visualize()`, or `run_notebook()` individually.
- Processing is slow and already run once? Set `should_process_data = FALSE` in
  `config.R`'s `initialize_startr()` call to skip re-running `process.R` — remember to
  flip it back to `TRUE` once processing code changes.

## Dependencies

This project uses [renv](https://rstudio.github.io/renv/) for reproducible package
versions (`renv.lock`). After adding a package name to `config.R`'s `packages` vector:

1. Restart R (or re-source `config.R`) so `initialize_startr()` installs it.
2. Run `renv::snapshot()` to lock the version before committing.

Don't hand-edit `renv.lock`.
